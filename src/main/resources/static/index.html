A. Overview

Aim: To design, build, and demonstrate an end-to-end Continuous Integration and Continuous Deployment (CI/CD) pipeline for a full-stack Spring Boot inventory management application featuring automated unit testing (JUnit 5), API integration testing (MockMvc), contract testing (Pact), real container testing (Testcontainers), local Git repository tracking, Docker image containerization, and canary deployment release management.

What is CI/CD?

Continuous Integration (CI): The automated practice of frequently merging code changes into a shared Git repository. Each push or pull request triggers an automated build and multi-tier test suite to detect bugs and integration mismatches immediately.

Continuous Delivery / Deployment (CD): The automated process of packaging validated code into deployable container artifacts (Docker images) and releasing them to target infrastructure using safe rollout strategies such as Canary releases.

Pipeline Stages Explained

Stage Tool / Technology Objective
1. Code Push Git / GitHub Repository Developer commits code to the main branch or opens a Pull Request.
2. Build Apache Maven & JDK 17 Compiles Java source code, downloads dependencies, and validates configuration.
3. Automated Tests JUnit 5, MockMvc, Pact, Testcontainers Executes service unit tests, web integration tests, contract verification, and container tests.
4. Docker Image Multi-Stage Dockerfile Builds a lightweight, secure container image containing the executable Spring Boot JAR.
5. Registry & CD Container Registry & GitHub Actions Tags and publishes image (experiment-9-app:latest) ready for cloud deployment.
6. Monitoring Telemetry & Health Probes Continuously assesses latency, HTTP 200 rates, and error frequencies.
7. Canary Rollout Reverse Proxy / Router Routes an initial 10% traffic to the canary release (v2.0.0), scaling up to 100% or rolling back on anomaly.

    1. CI Pipeline Workflow Definition (.github/workflows/ci.yml)

    Dedicated purely to Continuous Integration: Triggers on push or PR to main, provisions JDK 17, compiles code, runs all unit/integration/contract tests, and uploads surefire test reports.

    View CI Workflow Runs on GitHub → 
    name: CI Pipeline - Automated Build & Testing
on:
  push:
    branches: [ "main" ]
  pull_request:
    branches: [ "main" ]
  workflow_dispatch:

jobs:
  build-and-test:
    name: Build & Test Suite
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Set up JDK 17
        uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'
          cache: maven

      - name: Compile Application
        run: mvn compile --batch-mode

      - name: Run Automated Tests
        run: mvn test --batch-mode

      - name: Upload Test Report Artifact
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: surefire-test-reports
          path: target/surefire-reports/

    2. CD Pipeline Workflow Definition (.github/workflows/cd.yml)

    Dedicated purely to Continuous Deployment & Canary Rollout: Triggers automatically when the CI pipeline passes on main or via manual release dispatch. Builds the multi-stage Docker image and deploys the Canary release (v2.0.0) alongside Stable (v1.0.0).

    View CD Workflow Runs on GitHub → 
    name: CD Pipeline - Containerization & Canary Deployment
on:
  workflow_run:
    workflows: ["CI Pipeline - Automated Build & Testing"]
    types: [ completed ]
    branches: [ "main" ]
  workflow_dispatch:
    inputs:
      canary_traffic_percentage:
        description: 'Initial Canary traffic percentage (e.g. 10, 25)'
        required: true
        default: '10'

jobs:
  docker-build-and-deploy:
    name: Build Docker Image & Deploy Canary Release
    if: ${{ github.event_name == 'workflow_dispatch' || github.event.workflow_run.conclusion == 'success' }}
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Build Docker Image
        run: |
          docker build -t experiment-9-app:v2.0.0 -t experiment-9-app:latest .
          docker images

      - name: Deploy Canary Release
        run: |
          echo "Deploying Canary release v2.0.0 alongside Stable v1.0.0"

    E. Docker and Continuous Deployment (Container Registry)

    Packages the verified Spring Boot application into an immutable container image with multi-stage build optimization and non-root security compliance.

    Multi-Stage Dockerfile (Dockerfile)

    # Stage 1: Build stage with Maven and JDK 17
FROM maven:3.9.6-eclipse-temurin-17 AS builder
WORKDIR /workspace/app
COPY pom.xml .
RUN mvn dependency:go-offline -B
COPY src ./src
RUN mvn clean package -DskipTests

# Stage 2: Minimal Runtime JRE image
FROM eclipse-temurin:17-jre-jammy
WORKDIR /app
RUN useradd -u 1001 -m cicduser
USER cicduser
COPY --from=builder /workspace/app/target/experiment-9-cicd-pipeline-1.0.0.jar app.jar
EXPOSE 8089
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
  CMD curl -f http://localhost:8089/api/pipeline/overview || exit 1
ENTRYPOINT ["java", "-jar", "app.jar"]
